# Подготовка корпуса документов к загрузке в векторную базу

Инструмент превращает папку с инструкциями в формате Word в файл
`chunks_*.jsonl`, готовый к загрузке в векторную базу.

Вырос из рабочего конвейера, которым подготовлены пять корпусов: 169 документов,
2 478 фрагментов, 362 распознанных экрана. **Все правила ниже выведены из
поломок, а не придуманы заранее** — поэтому у каждой есть цена в числах.

## Когда брать и когда не брать

**Берите**, если документы — это инструкции по работе в программе: текст со
скриншотами, где половина смысла нарисована на картинке.

**Не берите**, если документы — сплошной текст без экранов. Половина
устройства здесь про скриншоты, и на чистом тексте вы заплатите сложностью ни
за что.

## Быстрый старт

```
python prepare_corpus.py --config config/мой-корпус.yaml
```

Перед первым запуском:

1. `pip install python-docx requests` — всё, других зависимостей нет. YAML
   разбирается своими силами, библиотека не нужна.
2. Скопировать `config/корпус.yaml.образец` → `config/мой-корпус.yaml` и
   прописать пути.
3. Скопировать `config/ключи.env.образец` → `config/ключи.env` и вписать ключ
   распознавания.

Пересобрать только нарезку, не ходя к модели:

```
python prepare_corpus.py --config config/мой-корпус.yaml --from-stage extract
```

Машинный отчёт для вызова из другой системы:

```
python prepare_corpus.py --config config/мой-корпус.yaml --json
```

Коды возврата — по ним ветвится вызывающий флоу:
`0` всё прошло · `1` собран, но есть замечания · `2` ошибка входа (нет конфига,
папки, ключа) · `3` не удалось распознать экраны.

## Шесть этапов

| этап | что делает |
|---|---|
| **Реестр** | строка на файл: формат, дата, объём, число экранов, годы скриншотов. Колонки ручной разметки при пересборке **не затираются** |
| **Извлечение** | docx → markdown с плейсхолдерами на местах картинок. Картинка привязана к абзацу, ПОСЛЕ которого стояла: «нажмите кнопку», следом экран с этой кнопкой. Здесь же вычищаются телефоны и пароли |
| **Распознавание** | каждый экран уходит в модель вместе с текстом вокруг него и возвращается разбором по шаблону: вкладки, кнопки, поля, флажки. Разобранные пропускаются — **повторный прогон ничего не стоит** |
| **Сборка** | разборы подставляются на места плейсхолдеров |
| **Нарезка** | по структуре документа, а не по числу знаков |
| **Проверка** | формат, семнадцать полей, нумерация, персональные данные, залипание модели, сокращения вне словаря |

## Семь правил, за каждым поломка

**1. Номера документов закрепляются сразу после первой сборки.** Таблица
`meta/docids.csv`. Без неё номера раздаются счётчиком по алфавиту, и первый же
новый файл сдвинет номера всех документов после себя — а они к этому моменту
уже стоят в журнале обращений, в отчётах и в метаданных каждого загруженного
фрагмента. Проверено на живом корпусе: добавление одного файла сдвигало
DOC-55 → DOC-56 и DOC-56 → DOC-57.

**2. Сверять надо НАРЕЗКУ, а не таблицы.** Проверка столкновений в таблицах
ничего не поймала, когда один номер принадлежал двум документам сразу: нарезка
отстала от таблиц. Таблица — намерение, нарезка — то, что поедет в базу.
Сверять надо выход.

**3. Распознавание идёт ДО разбора, а не после.** Порядок кажется
безразличным, пока в тексте не окажется нечитаемых знаков: источник чистый,
разбор грязный — значит испорчено при распознавании, и текстовой правкой это не
чинится.

**4. У модели выключены рассуждения, и это не оптимизация.** С включёнными она
уходила думать и возвращала пустой ответ. `thinking: disabled` — условие
работы.

**5. Есть отдельная проверка на залипание.** Модель один раз вернула километр
одного символа. Ответ формально валидный, все остальные проверки прошёл.

**6. Персональные данные сидят на КАРТИНКАХ.** Проверено структурно: все
находки пришлись на описания экранов, то есть значения напечатаны на
скриншотах. Текстовой правкой документа их не убрать — надо менять саму
картинку или выкидывать экран.

Поэтому найденное — не брак, а **вопрос к человеку**: документ не грузится и не
бракуется, а уходит в очередь «на подтверждение оператором». Находка бывает
ложной: «Россия Росма…» подходит под шаблон обрезанной фамилии, а это название
фирмы. Выбирает человек.

**7. Векторные экраны надо растеризовать.** Word хранит схемы процессов не
картинкой, а метафайлом Windows (EMF/WMF). Распознавание принимает только
растр, и такие экраны молча выпадали: в отчёте «формат не поддерживается», в
базе — дырка на месте схемы. В одном корпусе так терялось **127 экранов из
362**, и среди них все схемы процессов. Растеризацию делает
`pipeline/corpusprep/emf_v_png.ps1` — PowerShell, потому что единственный
надёжный рисовальщик EMF лежит в самой Windows.

## Чего этот инструмент НЕ делает

**Не определяет жанр документа по тексту.** Замер на 169 документах: лучший
порог по словам интерфейса даёт 88 %, и даже с полосой «не знаю» шириной в
треть корпуса семь настоящих инструкций отвергались бы молча. Инструкция и
журнал изменений про одно и то же написаны одними словами; различает их то,
зачем документ написан, а этого в тексте нет. **Жанр объявляется конфигом —
то есть папкой, в которую человек положил файл.**

**Не грузит в базу.** Отдаёт файл фрагментов; загрузка — отдельный шаг и
отдельный инструмент.

**Не решает за человека.** Спорное уходит в очередь, а не в базу.

## Что проверять перед правкой

```
python tests/run_regression.py
```

Собирает документы из `tests/fixtures/` и сравнивает результат с эталоном
**побайтно**. Правка, которая чинит один документ, обычно ломает другой — это
правило подтверждалось трижды.

**Эталонных документов в пакете нет.** Они были настоящими документами
компании, и класть их в переносимый инструмент нельзя. Как завести свои —
сказано в «ЧИТАТЬ ПЕРВЫМ».

## Рядом лежит ещё один инструмент

`sravnit_dokumenty.py` — сравнение документов: одно это или разное, чем
отличаются, что новее по четырём признакам дат. Плюс проверка, не стоит ли в
начале документа заголовок СОСЕДНЕГО файла. Режим `--papki` проходит корпус
целиком.

Нужен, потому что одна и та же инструкция приезжает тремя редакциями из четырёх
папок, и ни на одной нет пометки, какая из них действующая.
